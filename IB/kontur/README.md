### Отчет
### Часть 1. Соответствие требованиям нормативных документов

#### Вывод по Части 1:  
Приложение не соответствует требованиям Приказа ФСТЭК № 21 ни по одной из проверенных мер групп ИАФ, УПД, а также по ряду мер из групп ОП, ЗИС и РСБ. Заявленная возможность использования для ИСПДн до 4 УЗ не подтверждается. Использование приложения для обработки коммерческой тайны также невозможно из-за отсутствия механизмов разграничения доступа (нарушение ст. 10 ФЗ-98).

### Часть 2. Найденные уязвимости и слабости
**Уязвимость № 1. Открытые порты FTP (21) и SSH (22)**  

CWE-284 (Improper Access Control), CWE-319 (Cleartext Transmission)
Критичность	Высокая

FTP (порт 21) — протокол передачи данных в открытом виде. Логины, пароли и содержимое файлов передаются без шифрования и могут быть перехвачены сниффером трафика.

SSH (порт 22) — открыт для внешнего мира, что создаёт риск брутфорс-атак и эксплуатации уязвимостей в устаревшей версии OpenSSH (7.6p1, входящей в Ubuntu 18.04).

![k_port](https://github.com/DoctorZub/netology_homeworks/blob/main/img/IB/k_ports.jpg)
![k_ftp](https://github.com/DoctorZub/netology_homeworks/blob/main/img/IB/k_ftpserver.jpg)


Меры устранения:

- Отключить FTP-сервер, если он не используется.
- Заменить FTP на SFTP (часть SSH) или FTPS (FTP over TLS).
- Ограничить доступ к порту 22 по IP-адресам с помощью межсетевого экрана.
- Отключить аутентификацию по паролю в SSH, перейти на ключи.
- Установить Fail2Ban для защиты от брутфорса.

**Уязвимость № 2. Пароль администратора хранится в открытом виде** 

CWE-256 (Plaintext Storage of a Password), CWE-522 (Insufficiently Protected Credentials)
Критичность	Критическая

Файл доступен для чтения всем пользователям системы. Любой, кто получил доступ к серверу (даже с минимальными привилегиями), может прочитать пароль и войти в приложение как администратор.

![k_pass](https://github.com/DoctorZub/netology_homeworks/blob/main/img/IB/k_pasword.jpg)

Меры устранения:
- Хранить пароли только в виде хешей (bcrypt, Argon2).
- Ограничить права доступа к файлу: chmod 600 /opt/sk/password.txt.
- Удалить файл после первого запуска и предоставить механизм смены пароля через интерфейс.

**Уязвимость № 3. Пароль не маскируется при вводе**  

CWE-549 (Missing Password Field Masking), CWE-200 (Information Exposure)

На странице входа /login.html поле пароля имеет тип text вместо password, из-за чего вводимые символы отображаются открыто.  
Пароль можно подсмотреть визуально («плечевой серфинг») или через скриншот экрана. Это также увеличивает риск при записи экрана или демонстрации.

![k_passw](https://github.com/DoctorZub/netology_homeworks/blob/main/img/IB/k_web_password.jpg)

Меры устранения: Изменить атрибут поля ввода: "input type="password" name="password""

**Уязвимость № 4. Отсутствие защиты от брутфорса**  

CWE-307 (Improper Restriction of Excessive Authentication Attempts), CWE-521 (Weak Password Requirements)
Критичность	Высокая

Приложение не ограничивает количество неудачных попыток входа. Отсутствует CAPTCHA, задержка между попытками и блокировка учётной записи.  

Злоумышленник может подобрать пароль перебором. Особенно опасно в сочетании с уязвимостью № 2 (пароль в открытом виде), так как даёт второй вектор атаки.  


Меры устранения:
- Блокировка учётной записи после 5 неудачных попыток на 15–30 минут.
- Внедрение CAPTCHA после 3 неудачных попыток.
- Задержка между попытками (rate limiting).
- Уведомление администратора о множественных неудачных входах.

**Уязвимость № 5. Обход аутентификации и удаление файлов через /commercial/index.html**  

CWE-306 (Missing Authentication for Critical Function), CWE-862 (Missing Authorization)
Критичность	Критическая  
Страница /commercial/index.html доступна без аутентификации. Через неё можно удалять файлы, загруженные в приложение.

Критическая функция (удаление данных) не защищена проверкой подлинности пользователя. Любой, кто знает URL, может выполнить деструктивные действия.

![k_comm](https://github.com/DoctorZub/netology_homeworks/blob/main/img/IB/k_commercial.jpg)  

Также протестировал эту уязвимость с другого устройства
![k_phone](https://github.com/DoctorZub/netology_homeworks/blob/main/img/IB/k_iphone.jpg)

Меры устранения:
- Закрыть страницу аутентификацией: проверять сессию перед отдачей /commercial/*.
- Внедрить проверку авторизации на каждый запрос к критическим функциям.
- Использовать middleware для централизованной проверки прав доступа.

**Уязвимость № 6. Отсутствие Anti-CSRF токенов**  

CWE-352 (Cross-Site Request Forgery)
Критичность	Средняя/Высокая (зависит от других форм)  
HTML-форма на странице /login.html не содержит скрытого поля с анти-CSRF токеном.  

Злоумышленник может заставить аутентифицированного пользователя выполнить нежелательное действие (например, войти в чужую учётную запись — Login CSRF, или изменить данные).

Данную уязвимость нашел с помощью утилиты zaproxy на kali Linux

![K_sfr](https://github.com/DoctorZub/netology_homeworks/blob/main/img/IB/k_csrf.jpg)

Меры устранения:
- Генерировать уникальный CSRF-токен для каждой формы.
- Проверять токен при каждом POST-запросе.
- Установить флаг SameSite=Lax или Strict для сессионных cookie.
- Проверять заголовки Origin / Referer.



## Общий вывод
Проанализированное приложение «Защищённый контур» не может быть рекомендовано к использованию для построения ИСПДн до 4 УЗ включительно и для обработки коммерческой тайны. Выявлено 6 уязвимостей, из которых 2 — критического уровня (обход аутентификации с возможностью удаления файлов; хранение пароля в открытом виде). Приложение не соответствует требованиям Приказа ФСТЭК России № 21 по мерам групп ИАФ, УПД, а также ОП.1, ЗИС.1, РСБ.1. Нарушены требования ФЗ-98 «О коммерческой тайне» (ст. 10) в части разграничения доступа к конфиденциальной информации.
