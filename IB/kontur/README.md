### Отчет

#### Вывод по Части 1:  
Приложение не соответствует требованиям Приказа ФСТЭК № 21 ни по одной из проверенных мер групп ИАФ, УПД, а также по ряду мер из групп ОП, ЗИС и РСБ. Заявленная возможность использования для ИСПДн до 4 УЗ не подтверждается. Использование приложения для обработки коммерческой тайны также невозможно из-за отсутствия механизмов разграничения доступа (нарушение ст. 10 ФЗ-98).

#### Часть 2. Найденные уязвимости и слабости
Уязвимость № 1. Открытые порты FTP (21) и SSH (22)
Параметр	Значение
CWE	CWE-284 (Improper Access Control), CWE-319 (Cleartext Transmission)
Критичность	Высокая
CVSS	7.5 (High)
Слабость: На сервере открыты порты 21 (FTP) и 22 (SSH).

Уязвимость:

FTP (порт 21) — протокол передачи данных в открытом виде. Логины, пароли и содержимое файлов передаются без шифрования и могут быть перехвачены сниффером трафика.

SSH (порт 22) — открыт для внешнего мира, что создаёт риск брутфорс-атак и эксплуатации уязвимостей в устаревшей версии OpenSSH (7.6p1, входящей в Ubuntu 18.04).

Эксплуатация:

bash
# Перехват FTP-трафика с помощью tcpdump
sudo tcpdump -i eth0 -A port 21

# Сканирование портов с внешней машины
nmap -sV -p 21,22 192.168.1.153
Результат: При подключении к FTP и вводе учётных данных — логин и пароль видны в открытом виде в выводе tcpdump. При сканировании nmap подтверждается доступность портов из сети.

Меры устранения:

Отключить FTP-сервер, если он не используется.

Заменить FTP на SFTP (часть SSH) или FTPS (FTP over TLS).

Ограничить доступ к порту 22 по IP-адресам с помощью межсетевого экрана.

Отключить аутентификацию по паролю в SSH, перейти на ключи.

Установить Fail2Ban для защиты от брутфорса.

Уязвимость № 2. Пароль администратора хранится в открытом виде
Параметр	Значение
CWE	CWE-256 (Plaintext Storage of a Password), CWE-522 (Insufficiently Protected Credentials)
Критичность	Критическая
CVSS	9.0 (Critical)
Слабость: Пароль администратора записывается в файл /opt/sk/password.txt в открытом виде.

Уязвимость: Файл доступен для чтения всем пользователям системы. Любой, кто получил доступ к серверу (даже с минимальными привилегиями), может прочитать пароль и войти в приложение как администратор.

Эксплуатация:

bash
cat /opt/sk/password.txt
# Вывод: пароль в открытом виде
Результат: Получен пароль администратора приложения. Возможен полный контроль над приложением.

Меры устранения:

Хранить пароли только в виде хешей (bcrypt, Argon2).

Ограничить права доступа к файлу: chmod 600 /opt/sk/password.txt.

Удалить файл после первого запуска и предоставить механизм смены пароля через интерфейс.

Уязвимость № 3. Пароль не маскируется при вводе
Параметр	Значение
CWE	CWE-549 (Missing Password Field Masking), CWE-200 (Information Exposure)
Критичность	Средняя
CVSS	5.3 (Medium)
Слабость: На странице входа /login.html поле пароля имеет тип text вместо password, из-за чего вводимые символы отображаются открыто.

Уязвимость: Пароль можно подсмотреть визуально («плечевой серфинг») или через скриншот экрана. Это также увеличивает риск при записи экрана или демонстрации.

Эксплуатация:

Открыть /login.html.

Начать вводить пароль — символы видны на экране.

Результат: Пароль раскрывается визуально.

Меры устранения: Изменить атрибут поля ввода: <input type="password" name="password">.

Уязвимость № 4. Отсутствие защиты от брутфорса
Параметр	Значение
CWE	CWE-307 (Improper Restriction of Excessive Authentication Attempts), CWE-521 (Weak Password Requirements)
Критичность	Высокая
CVSS	7.5 (High)
Слабость: Приложение не ограничивает количество неудачных попыток входа. Отсутствует CAPTCHA, задержка между попытками и блокировка учётной записи.

Уязвимость: Злоумышленник может подобрать пароль перебором. Особенно опасно в сочетании с уязвимостью № 2 (пароль в открытом виде), так как даёт второй вектор атаки.

Эксплуатация:

bash
# Пример с Hydra
hydra -l admin -P /usr/share/wordlists/rockyou.txt 192.168.1.153 http-post-form \
  "/login:login=^USER^&password=^PASS^:F=incorrect"
Результат: При слабом пароле — подбор за минуты. При отсутствии блокировки — бесконечные попытки.

Меры устранения:

Блокировка учётной записи после 5 неудачных попыток на 15–30 минут.

Внедрение CAPTCHA после 3 неудачных попыток.

Задержка между попытками (rate limiting).

Уведомление администратора о множественных неудачных входах.

Уязвимость № 5. Обход аутентификации и удаление файлов через /commercial/index.html
Параметр	Значение
CWE	CWE-306 (Missing Authentication for Critical Function), CWE-862 (Missing Authorization)
Критичность	Критическая
CVSS	9.8 (Critical)
Слабость: Страница /commercial/index.html доступна без аутентификации. Через неё можно просматривать и удалять файлы, загруженные в приложение.

Уязвимость: Критическая функция (удаление данных) не защищена проверкой подлинности пользователя. Любой, кто знает URL, может выполнить деструктивные действия.

Эксплуатация:

Перейти по адресу http://192.168.1.153:8888/commercial/index.html без входа в систему.

В интерфейсе страницы найти список файлов и кнопку удаления.

Нажать «Удалить» — файл удаляется.

Результат: Несанкционированное удаление файлов, содержащих коммерческую тайну или персональные данные. Прямое нарушение ст. 10 ФЗ-98 и мер УПД.2, ЗИС.1 Приказа № 21.

Меры устранения:

Закрыть страницу аутентификацией: проверять сессию перед отдачей /commercial/*.

Внедрить проверку авторизации на каждый запрос к критическим функциям.

Использовать middleware для централизованной проверки прав доступа.

Уязвимость № 6. Отсутствие Anti-CSRF токенов
Параметр	Значение
CWE	CWE-352 (Cross-Site Request Forgery)
Критичность	Средняя/Высокая (зависит от других форм)
CVSS	6.5 (Medium)
Слабость: HTML-форма на странице /login.html не содержит скрытого поля с анти-CSRF токеном.

Уязвимость: Злоумышленник может заставить аутентифицированного пользователя выполнить нежелательное действие (например, войти в чужую учётную запись — Login CSRF, или изменить данные).

Эксплуатация:

Создать HTML-файл:

html
<form action="http://192.168.1.153:8888/login" method="POST" id="csrf">
    <input type="hidden" name="login" value="admin">
    <input type="hidden" name="password" value="attacker_pass">
</form>
<script>document.getElementById('csrf').submit();</script>
Открыть файл в браузере жертвы, где активна сессия приложения.

Форма автоматически отправит POST-запрос от имени жертвы.

Результат: Выполнение действия от имени пользователя без его ведома.

Меры устранения:

Генерировать уникальный CSRF-токен для каждой формы.

Проверять токен при каждом POST-запросе.

Установить флаг SameSite=Lax или Strict для сессионных cookie.

Проверять заголовки Origin / Referer.

Общий вывод
Проанализированное приложение «Защищённый контур» не может быть рекомендовано к использованию для построения ИСПДн до 4 УЗ включительно и для обработки коммерческой тайны. Выявлено 6 уязвимостей, из которых 2 — критического уровня (обход аутентификации с возможностью удаления файлов; хранение пароля в открытом виде). Приложение не соответствует требованиям Приказа ФСТЭК России № 21 по мерам групп ИАФ, УПД, а также ОП.1, ЗИС.1, ЗИС.2, РСБ.1. Нарушены требования ФЗ-98 «О коммерческой тайне» (ст. 10) в части разграничения доступа к конфиденциальной информации.

Первоочередные меры:
Закрыть страницу /commercial/* аутентификацией (уязвимость № 5).

Удалить пароль из открытого файла, внедрить хеширование (уязвимость № 2).

Внедрить блокировку после неудачных попыток входа (уязвимость № 4).

Отключить FTP, ограничить доступ к SSH (уязвимость № 1).

Внедрить CSRF-токены (уязвимость № 6).

Исправить маскировку пароля (уязвимость № 3).

Обновить ОС и приложение до поддерживаемых версий.
